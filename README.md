# NICE FAITH LAB

SolidJS + TypeScript + Vite 모바일 우선 신앙활동 시뮬레이션입니다. 금융 신용평가 경험을 패러디한 독립 교육 앱이며 실제 NICE 신용평가사와 무관합니다.

## 작업 위치

현재 소스: `/Users/denver/workspaces/nice-faith/`

이전 Codex 폴더는 백업으로 보존했습니다. 이후 실행·수정·Git 저장소 연결은 새 폴더에서 진행하세요.

## 실행

Node.js 24 권장. 설치된 의존성과 잠금 파일은 기존 버전을 유지합니다.

```sh
cd ~/workspaces/nice-faith
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run preview
```

`dev`는 개발 서버, `preview`는 빌드된 `dist/`를 사용합니다. 두 모드 모두 기본/개인별 OG 메타데이터를 서버 응답에 넣습니다.

## 사용자 흐름

- Q1–Q11은 선택 후 300ms 뒤 다음 질문으로 이동합니다. 동작 줄이기 환경에서는 지연하지 않습니다.
- 이전/다음 버튼은 같은 폭이며 이전 버튼도 강조합니다. 진행 중 이전으로 이동하거나 화면을 떠나면 대기 중인 자동 이동을 취소합니다.
- Q12는 선택만으로 이동하지 않고 ‘결과 확인하기’를 눌러야 합니다.
- 질문 건너뛰기와 분석 취소는 유지합니다. 분석·반전의 애니메이션 건너뛰기 버튼은 제거했습니다. 동작 줄이기 설정은 유지합니다.
- 결과의 핵심 점수와 ‘이 점수의 의미 확인하기’를 상단에 배치했습니다. 영역별 분석과 산정 설명은 기본적으로 접혀 있습니다.
- 점수는 감소시키지 않고 소멸시킵니다. 최종 성찰 화면은 점수·등급·그래프를 재표시하지 않습니다.
- 시작·설문·결과·성찰 사이의 브라우저 뒤로/앞으로 이동과 답변 수정을 지원합니다. 다시 시작 및 새로고침은 응답을 초기화합니다.

## 공유 링크와 Open Graph

공유 예시: `https://배포주소/?score=730&name=아무개`.

구분자는 `&`이며, 앱은 `URLSearchParams`로 이름을 URL 인코딩합니다. 선택적 별명은 최대 20자이며 표시용 문자만 허용합니다. 점수는 정수 1–1,000만 허용하며, 중복 점수·이름이나 잘못된 점수는 공유 결과로 취급하지 않습니다.

링크를 열면 해당 점수·이름·점수에서 계산한 가상 등급과 ‘나도 측정해보기’를 먼저 표시합니다. 별도 설문 답변이 없으므로 영역별 세부 점수나 개인화 성찰은 만들어 내지 않습니다. 새 설문 시작 시 받은 점수와 이름을 URL에서 제거합니다.

- 썸네일: `public/og-default.png`, 800×400, PNG 약 38KB. 카카오톡 URL 미리보기용 2:1 비율.
- 이미지 자체는 고정입니다. 사용자별 이미지 파일을 생성하지 않습니다.
- 점수·이름은 HTML의 `og:title`, `twitter:title`과 공유 결과 화면에 반영합니다.
- 기본 description은 ‘12개의 질문, 나의 신앙활동은 몇 점일까요?’이며 반전의 내용을 공개하지 않습니다.
- Vercel의 `api/page.ts`가 빌드된 앱 HTML에 OG 태그를 넣어서 반환합니다. 클라이언트 JavaScript를 실행하지 않는 수집기도 읽을 수 있습니다.
- `server/page.ts`는 메타데이터 작성과 HTML 이스케이프를 담당합니다. 프런트와 동일한 URL 검증 함수를 사용합니다.
- `vercel.json`은 `/`와 `/index.html`을 해당 함수로 연결하고 빌드 HTML을 함수에 포함합니다.
- 서버 응답에 배포 호스트의 절대경로 이미지 주소를 사용하므로 별도 사이트 주소 환경변수가 필요하지 않습니다.

공유 링크의 점수와 이름은 누구나 수정할 수 있습니다. 이 기능은 인증이나 순위 시스템이 아닙니다. 점수의 진위를 검증하는 서버나 서명은 두지 않았습니다.

## 개인정보

설문 답변과 개인화 성찰은 브라우저 메모리에만 존재합니다. 로그인·DB·분석 도구·쿠키·localStorage·sessionStorage를 사용하지 않습니다.

사용자가 공유를 누르면 점수와 입력한 별명만 공개 URL에 포함됩니다. 이 두 항목은 수신자·호스팅 접속 로그·링크 미리보기 서비스에서 볼 수 있습니다. 공유 입력 옆에 이를 안내합니다. 답변·영역별 점수·개인화 성찰을 URL이나 서버로 전송하지 않습니다. 외부 성경 링크에는 referrer를 전송하지 않습니다.

## Vercel 배포

1. 이 폴더를 GitHub 저장소에 올립니다. `node_modules/`, `dist/`, `work/`, `.vercel/`은 제외합니다.
2. Vercel에서 해당 저장소를 Import합니다.
3. Framework Preset: **Vite**, Build Command: **npm run build**, Output Directory: **dist**, Node.js: **24.x**.
4. Root Directory는 `package.json`과 `vercel.json`이 있는 폴더입니다.
5. 환경변수 없이 Deploy합니다. 함수와 정적 파일이 함께 배포됩니다.
6. 배포 URL과 `/?score=730&name=아무개`를 열어 각각 기본·공유 결과를 확인합니다.
7. 카카오톡 미리보기 검수는 공개된 프로덕션 URL로 수행합니다. 배포 보호 화면이 있는 프리뷰 URL은 카카오 수집기가 읽지 못할 수 있습니다.

현재 버전은 링크별 OG 태그 때문에 Vercel Function이 필요합니다. `dist/`만 다른 정적 호스팅에 올리면 링크별 OG 메타데이터가 작동하지 않습니다. Cloudflare Pages용 서버 설정은 포함하지 않습니다.

카카오톡 미리보기는 캐시되므로 기존 링크가 갱신되지 않으면 [카카오 OG 캐시 초기화 도구](https://developers.kakao.com/tool/clear/og)를 사용하세요. 실제 표시·이미지 크롭은 카카오 서비스가 결정합니다.

## 검증과 구조

- `src/data/questions.ts`: 질문·선택지·점수 정의.
- `src/domain/scoring.ts`: 결정적 채점·등급·영역·기여도 산출.
- `src/domain/sharing.ts`: 공개 점수·이름의 입력 검증과 URL 생성.
- `src/components/ShareControls.tsx`: 선택적 이름·공유·주소 복사·직접 복사 대체.
- `src/screens/SharedResultScreen.tsx`: 공유 결과 첫 화면.
- `src/tests/`: 기존 채점 경계·결정성과 자동 이동·공유·OG HTML·서버 처리 검증.
- `scripts/create-thumbnail.swift`: macOS 기본 글꼴·도형으로 정적 썸네일 재생성. 배포 빌드는 Swift를 요구하지 않습니다.

Q1–Q10만 채점하며 Q11·Q12는 성찰 문구에만 사용합니다. 미응답·평가 제외는 중립값 50, 채점 가능한 응답이 없으면 결과 산출을 거부합니다. 영역의 중간값을 반올림하지 않습니다. 계산식은 `1 + Math.round(999 * sum(domainScores) / 500)`이며 기존 채점 규칙은 유지했습니다.

## 남은 확인 사항

개역개정 발췌문은 번역문 사용 조건을 공식 자료로 확인하지 못해, 에베소서 2:8–10의 자체 설명과 대한성서공회 본문 링크로 대체한 상태입니다.

외부 Vercel 배포 및 실제 카카오톡 수집은 아직 수행하지 않았습니다. 로컬 프로덕션 HTTP 응답·브라우저 검수와 자동 테스트를 제공합니다.
